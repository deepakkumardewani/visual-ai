# Spec: Media Studio (Audio, Video, Tools expansion)

Status: DRAFT for human review. Source of truth for paths and symbols: `agent_docs/media-studio/REPO_MAP.md` and `docs/MODEL_ONBOARDING.md`. Anything not in the map is marked **(new)**. Replicate facts below were read from each model's public page and embedded OpenAPI schema (no predictions were run, nothing was billed). Research date: 2026-11-15; prices change, so every price is a config constant, never a literal in logic.

## 1. Objective

Expand the app from image-only to a phased media studio: Song studio, Music, Speech (TTS), Video, and Tools (image watermark, video watermark, autocaption, sketch-to-image). Each feature must feel finished: priced up front, editable output, saved to history, polished empty/loading/error states, keyboard and mobile support.

Users: existing Visual AI creators (free and Pro) who already buy credits. Success: a user can go from idea to exported, playable audio/video/asset without leaving the app, and always knows the credit cost before pressing Generate.

Phase order (one plan): **P0 shared infra -> P1 Song -> P2 Music -> P3 TTS -> P4 Video -> P5 Tools**.

## 2. Findings that shape the plan (read first)

1. **There is no existing video section anywhere in the repo (audited 2026-11-15).** `FeatureType` in `packages/shared/src/types/domain.ts` is `IMAGE | UPSCALE | COLORIZE | REVIVE | REMOVE_BG`; `FEATURES` in `apps/web/src/utils/constants.ts` has no video entry; `apps/web/src/router/index.ts` has no video route; `apps/web/src/pages/` has no video page; `apps/api/src/routes/` has no video endpoint (`generate.ts` serves only `/generate/image`, the four utility routes and `/generate/reference-images`); `NavTabs.vue` and `dashboardRoutes.ts` have no video tab. No local or remote branch contains video source files (only intro/landing `.mp4`/`.webm` marketing clips). The only traces are anticipatory: the `PAID_PATH_PATTERN` const inside `apps/web/e2e/support/paidCallGuard.ts` (not exported) already matches `POST /generate/video` and `/generate/<op>/video`, which is why the project CLAUDE.md names `POST /generate/video`; a commented-out `VideoFeature` interface in `apps/web/src/types/index.ts`; and an `.mp4` fixture in `apps/web/e2e/fixtures/assets/`. Decision D1: Video is built **from scratch** as a new `/video` page in P4 (the header's "Video" item), with `prunaai/p-video` and `alibaba/wan-3` as its first two models.
2. **Model registry is image-shaped.** `MODEL_REGISTRY` in `packages/shared/src/models/registry.ts` and `ModelDefinition` in `types.ts` only model image fields (`aspectRatio`, `outputFormat`, `outputQuality`, `numOutputs`, `resolution`, `dimensions`, `imageInput`, `promptEnhance`) and `pricePerImage`. Audio/video/tool models need a media-aware extension (R-INF-1).
3. **Existing credit pattern = flat integer cost per model, charged only on success, no refund code.** `getCreditCost` in `packages/shared/src/models/credits.ts` is a per-model lookup (budget/standard 1, premium `PREMIUM_CREDIT_COST` = 5, utilities 2, premium upscalers 4); `calculateCreditCost` in `apps/api/src/utils/credit-calculator.ts` wraps it. `runGenerationJob` in `apps/api/src/services/generation-service.ts` runs `model run -> store in DB -> deduct credits -> upload to Cloudinary -> complete`; deduction is one atomic two-bucket `findOneAndUpdate` (daily first, then persistent) that throws "Insufficient credits". Affordability is checked **only client-side** (`canAffordGeneration` / `getGenerationCreditCost` in `apps/web/src/utils/generationCredits.ts`, used by `stores/user.ts`); `routes/generate.ts` does no server credit check before `enqueueGeneration`. Consequences: a failed Replicate run is never charged (the existing "refund" is "never charged"); there is no refund/release code; a run whose deduction fails after success errors out and the Replicate cost is absorbed. This spec keeps that pattern as the default (R-INF-6); reserve-then-settle is not used (the confirmed intent is the existing pattern; residual risk in Q3).
4. **Credit value and margin from repo numbers:** `CREDIT_PACKS` in `packages/shared/src/models/creditPacks.ts` (INR) gives INR 0.65/credit (`pack_200`, 200 for INR 130) down to INR 0.45/credit (`pack_2000`, 2000 for INR 900); the largest pack is worst-case revenue per credit. FX is live via `getFxRates` in `apps/api/src/payments/fx.ts`. **No margin constant exists**: `docs/MODEL_ONBOARDING.md` and `docs/PRD.md` only say "credits ≈ Replicate cost × margin", and the existing image prices are not a consistent multiple of `pricePerImage` (`FLUX_PRO` 5 credits for $0.04 and `NANO_BANANA_2` 1 credit for $0.067 both sell at or below Replicate cost at the base pack; `NANO_BANANA_PRO` 5 credits for $0.15 is well below). So there is no existing margin to copy; decision D2 fixes the media multiplier at `MEDIA_CREDITS_PER_USD = 200` (section 8).
5. **Lyrics LLM already exists and is DeepSeek:** the app's text LLM is DeepSeek via `@ai-sdk/deepseek` with model `env.ENHANCE_MODEL` (default `deepseek-chat`, `apps/api/src/config/env.ts`), used by `improveUserPrompt`/`generateRandomPrompt` (`apps/api/src/lib/prompt-actions.ts`), `enhancePrompt` (`prompt-enhancer.ts`) and `checkPromptSafety` (`prompt-moderation.ts`), all through `generateText` from `ai` with per-call timeouts. Anthropic (`env.DESCRIBE_MODEL`, default `claude-sonnet-4-5`) is used only for image description (`describeImageFromBuffer`) and is **not** used for lyrics. Lyrics generation reuses the DeepSeek model via a new module (R-SONG-3).
6. **Replicate gotchas discovered:**
   - `charlesmccarthy/addwatermark` schema accepts only `video`, `watermark` (text, default "FULLJOURNEY.AI") and `size` (integer font size 1-500, default 40); no README. **No position, opacity, colour or logo input**, so decision D4: video watermark uses this model with its fixed position, text and size only (R-TOOL-VW-1); image watermark keeps full visual placement.
   - `prunaai/p-video` has `disable_safety_filter` defaulting to **true**; we must always send `false`.
   - `minimax/voice-cloning` (verified 2026-11-15): inputs `voice_file` (MP3/M4A/WAV, 10 s-5 min, < 20 MB), `model` enum **`speech-02-turbo | speech-02-hd` only** (default `speech-02-turbo`), `accuracy` 0-1 (default 0.7), `need_noise_reduction`, `need_volume_normalization`; billed **$3 per output** (per clone). The `minimax/speech-2.8-hd`/`-turbo` schemas state `voice_id` accepts "a voice_id returned by https://replicate.com/minimax/voice-cloning", and the Replicate TTS collection FAQ says both 2.8 models support cloning; so the documented flow is: clone once with `minimax/voice-cloning`, store the returned `voice_id`, pass it as `voice_id` to 2.8. Only voice expiry remains unverified (Q5).
   - Minimax speech is billed per 1K **input tokens** on Replicate (`token_input_count`), not characters; Inworld and Chatterbox bill per 1K input characters (`character_input_count`); Minimax music bills per output file (`audio_output_count`). These billing metrics were read from each page's `billingConfig` on 2026-11-15.
   - Replicate output URLs are temporary; all outputs must be copied to our storage (R-INF-5).
   - `stable-audio-2.5` and `music-*` are billed **per output file**; `lyria-2` is billed per second of output but always returns a fixed 30 s clip, so it is effectively per file.
   - The `paidCallGuard.ts` pattern covers only paths ending in `image` or `video` under `/generate/`; new `/generate/audio/*`, `/generate/tools/*` and the outbound-LLM `/prompt/lyrics` route are **not** covered today (R-INF-9).

## 8. Credit formulas

Definitions (new constants in `packages/shared/src/models/credits.ts`, extend): `MEDIA_CREDITS_PER_USD = 200` (decided, D2; the single source for every media credit price), `MIN_JOB_CREDITS = 1`. Credits are integers. Derivation from the repo: `creditPacks.ts` sells a credit for INR 0.65 (pack_200, 13000 paise / 200) down to INR 0.45 (pack_2000, 90000 / 2000); `apps/api/src/payments/fx.ts` fetches a live USD rate daily (no fixed constant in the repo), so at a reference rate of INR 88 per USD (`FX_REFERENCE_INR_PER_USD = 88`, new, documentation and tests only) that is USD 0.0074 to 0.0051 per credit, so 200 credits per USD of Replicate cost is about 1.5x cost at pack_200 and about 1.0x (break-even) at pack_2000. The repo has no margin constant and existing image prices are not cost-derived (section 2 finding 4), so the owner set this multiplier (D2).

`credits = max(MIN_JOB_CREDITS, ceil(replicateCostUSD * MEDIA_CREDITS_PER_USD))`. Cost is computed by `getMediaCreditCost` from the user's chosen options before Generate, and the server recomputes it from the validated body (the client figure is never trusted).

## 9. FAQ content draft (Speech)

Derived from the Replicate text-to-speech collection page FAQ (which model to start with, most expressive, fastest, cloning, most languages, emotions, commercial use) and the five model READMEs/schemas, restricted to the five supported models.

1. **Which model should I pick?** For the most expressive, steerable delivery pick **Inworld TTS 2** (write directions in brackets like `[whisper in a hushed style]`). For solid quality with fixed emotion tags at a lower price pick **Inworld TTS 1.5 Max**. For long scripts (up to 10,000 characters), many languages, voice cloning and fine control of speed, pitch and volume pick **Minimax Speech 2.8 HD** (best fidelity) or **2.8 Turbo** (faster, cheaper). For short clips and quick drafts pick **Chatterbox Turbo** (up to 500 characters, lowest cost).
2. **How do tags like laugh or sigh work?** Type `/` in the editor and choose a tag. Each model uses its own syntax, we write it correctly for you. Only tags the selected model supports are shown.
3. **What happens to my tags when I switch models?** Your text is never lost. Tags the new model cannot perform are highlighted so you can convert, edit or remove them. Unsupported tags are left out of the generated audio.
4. **Why is my text limit different per model?** Limits come from the model: 2,000 characters for Inworld, 10,000 for Minimax, 500 for Chatterbox. Tags count toward the limit.
5. **How much does it cost?** You see the exact credits before you press Generate, based on the character count. Failed generations do not use credits.
6. **Which languages are supported?** Inworld: 15 production languages (English, Chinese, Japanese, Korean, Russian, Italian, Spanish, Portuguese, French, German, Polish, Dutch, Hindi, Hebrew, Arabic), Inworld 2 also has experimental support for 90+ more. Minimax Speech 2.8 HD: 32+ languages; 2.8 Turbo: 40+ languages; both accept a language hint. Chatterbox: best in English.
7. **How do I add pauses?** Use the Pause tag in the `/` menu (Inworld 1.5 Max and Minimax). For Inworld 2 use a direction such as `[say with deliberate pauses]`.
8. **Can I clone my voice?** Yes, on Minimax 2.8 models. Upload 10 seconds to 5 minutes of clean audio (MP3, M4A or WAV, under 20 MB) and confirm you own the voice or have the right to use it. Cloning costs credits once.
9. **Is it OK to clone someone else's voice?** Only with their permission. You must confirm this before cloning, and we keep a record of the confirmation.
10. **Can I use the audio commercially?** "Most of these models allow commercial use, but each has its own license. Check the model's license and our Terms before publishing." (Wording mirrors the collection page; final legal copy is Q8, non-blocking.)
11. **Why does the generated speech sound different each time?** Models sample randomly; lower the `temperature` or set a seed (where available) for repeatable results.
12. **Can I edit the audio after generating?** Yes: trim, fade, change volume and speed, loop, and export MP3 or WAV right on the result.
13. **Is this real-time streaming?** No. Generation takes a few seconds and the finished file is saved to History.

## 10. UX notes (opinionated; apply the `impeccable` skill and its `critique`, `polish`, `layout`, `typeset`, `normalize` passes; never `frontend-design`)

General: follow the existing token system (`tailwind.semantic-plugin.js`, existing primitives under `components/primitives/`), reuse `CustomButton`, `AppModal`, `Popover`, `Tooltip`, `Toast`, `SegmentedControl`, `CreditCostBadge`. No default-AI look: avoid gradient purple hero blocks, avoid emoji icons, avoid identical card grids with rounded-everything. Pick one distinctive visual idea per studio and carry it through.

- **Direction:** the Audio surfaces feel like a precise instrument, not a toy: calm neutral canvas, one accent colour per studio used sparingly (Song = warm, Music = cool, Speech = green/teal), large tabular numerals for time and cost, monospace-ish timecodes, generous spacing, strong type hierarchy (typeset pass: one display size for the page title, one for section titles, small caps labels for controls).
- **Layout:** desktop is two columns: left "compose" column (max about 560 px), right "result and editor" column that sticks while the left scrolls. Mobile: single column; the action bar (cost + Generate) is sticky at the bottom; the editor opens as a full-height bottom sheet. Cost badge always adjacent to Generate; it animates (number tween, existing `AnimatedCounter.vue`) when options change.
- **Waveform editor:** waveform in the accent colour at 60% with played portion at full strength, centered playhead on scrub, region in a translucent accent with clearly graspable 12 px handles (touch: 24 px hit area), timecodes at the left/right edges and under the playhead, controls grouped in a toolbar: transport | region | fades | volume | speed | export. A "snap to zero crossings" hint avoids clicks when trimming. Export button is primary only on the edited state; when nothing changed it offers "Download original".
- **Mini-player:** a slim bar (56 px) with title, play/pause, scrub, time, and a small waveform sparkline; slides up (200 ms ease-out) and down; does not cover the sticky action bar (stacked above it on mobile). Close ends playback.
- **Genre/mood picker:** chips grouped with a search field on top; selected chips show a check and stack into a "Your sound" summary line; at limit the remaining chips dim with a tooltip rather than hiding.
- **Lyrics editor:** section cards with a coloured left rule per section type, drag handle, inline "Regenerate section"; character budget as a thin progress bar with a numeric "420 / 600"; over budget turns the bar and counter to the error token and adds a sentence ("Music 1.5 accepts up to 600 characters. Condense or switch to 2.6").
- **TTS editor:** looks like a writing surface (large type, comfortable measure of about 68 characters, line-height 1.6), not a form field. Slash menu is a compact popover (max 8 visible rows, scrollable) with group headings, a keyboard hint footer ("Up/Down to move, Enter to insert, Esc to close"), and each row showing the tag preview (e.g. `laugh` + `[laugh]` syntax in muted monospace). Chips: pill shape, 20 px height, group colour tokens at 14% tint with 100% text (WCAG AA contrast checked in both themes), icon + word, a distinct shape for pauses (shows the duration). Unsupported chips: diagonal-stripe warning border plus the label, never just colour. The model switch banner appears above the editor, persistent until resolved, with counts.
- **Model advisor and FAQ:** friendly but concise; the quick picker is 3 chips, answer is a card with "Recommended: X" and a one-line reason; FAQ is an accordion (reuse `Accordion.vue`/`FAQ.vue`) with deep-linkable questions.
- **Voice clone dialog:** step list (Upload, Consent, Name, Clone), file drop zone with real-time duration/size validation messages, a waveform preview and a "Needs 10 s minimum" progress hint, consent checkbox in a bordered block with the exact legal-style sentence and a link to the terms; the primary button disabled with an explanation until checked.
- **Video:** prompt first, big; mode tabs (Text / Image / Audio) with thumbnails; resolution and duration as a segmented control + slider with the cost updating live; draft toggle as a callout card ("Try cheap first") with the saved-credits number.
- **Tools:** each tool is a canvas-first layout: the preview stage is the hero (checkerboard for transparency, safe zones for captions), controls live in a right inspector panel (bottom sheet on mobile). Drag handles for watermark placement show snapping guides and a position readout.
- **States:** (1) Empty: one useful example/action, never an illustration only. (2) Loading: skeletons for waveform and cards; generation progress shows stage text ("Queued", "Composing", "Mastering", "Saving") with elapsed time and "you can leave this page". (3) Error: say what happened, whether credits were used ("No credits were used."), and the single next step (Retry, Edit prompt); content-safety refusals use neutral wording and suggest a rewrite. (4) Success: a toast plus the result card scrolled into view, focus moved to the Play button. (5) Offline/timeouts: retry with exponential back-off messaging.
- **Motion:** purposeful only: 150-250 ms ease-out for popovers, spring-free; scrubbing and playhead are not animated beyond RAF; respect reduced motion.
- **Accessibility:** WCAG AA contrast, visible focus rings, ARIA for custom controls (slider roles for fades, listbox for the slash menu), no seizure-risk flashes in loading states, captions/transcript for any spoken sample content.
- **Keyboard shortcuts:** exactly the `MEDIA_SHORTCUTS` list in R-INF-15, plus `/` inside the TTS editor (R-TTS-3). No other shortcuts.

## 12. Testing strategy

- **Unit (Vitest):** `getMediaCreditCost` per model (table-driven from section 8); `serializeTts` per model plus round trips and the 6.5 conversion map; schema validation per model (limits, mutual exclusions, ignored-input rules); `media-input.ts` payload builders (never sends unsupported fields, always `disable_safety_filter:false`); lyrics JSON parsing and budget trimming; media job credit flow (deducts exactly `getMediaCreditCost` once on success, deducts nothing on Replicate failure/moderation/timeout, server recompute ignores a client-sent cost); 402 `INSUFFICIENT_CREDITS` pre-check; duplicate `jobId` rejected; `paidCallGuard` pattern matches `/generate/audio/*`, `/generate/tools/*`, `/generate/video`, `/prompt/lyrics`; `MEDIA_SHORTCUTS` keys unique against existing shortcuts; WAV encoder correctness; fade/trim math; region/loop state.
- **Component:** TTS editor (slash menu filtering, chip insert/delete, model-switch flagging, over-limit), waveform editor controls (with a mocked WaveSurfer), voice clone dialog consent gating, header dropdown keyboard behaviour, mini-player store.
- **E2E (Playwright, all paid calls mocked):** one scenario per feature (Song end-to-end with a stubbed lyrics endpoint, Music, Speech incl. tag insert and model switch, clone with consent, Video draft->final, each Tool, sketch-to-image), plus mini-player persistence across navigation, balance drops by the shown cost on success, balance unchanged on a stubbed failure, LowCreditsDialog on a stubbed 402. The `paidCallGuard` must fail on any un-intercepted paid path, including the new audio, tools and lyrics paths.
- **Manual verification:** per phase, the verifier runs the acceptance criteria in the browser (agent-browser) with the e2e user; no real Replicate calls.
- **Quality gates per phase:** `bun run check`, `bun run test`, `bun run check:model-docs`, a11y checks on new pages, Lighthouse perf spot-check of editor pages (no main-thread export jank).

## 14. Assumptions

- **A4:** Minimax tokens are approximated as characters for pre-cost; the post-run actual may differ; costs are rounded up and the difference is absorbed by margin.

- **A6:** Voice rows show README text descriptions only; audio previews would need paid generation and are deferred (owner may add static clips later without spec change).

- **A9:** Cloudinary accepts audio and video under `resource_type: 'video'`; plan limits on file size (free tier ~100 MB per asset) are sufficient for 6-min tracks and 30 s 1080p videos (to be verified in P0).

- **A11:** TipTap is user-approved; wavesurfer.js and a lame-based encoder (`@breezystack/lamejs`) are approved new dependencies (owner, 2026-11-16).
