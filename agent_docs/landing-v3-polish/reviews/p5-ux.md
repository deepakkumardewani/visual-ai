## BLOCKING

- P5 · [a11y] · apps/web/src/components/LandingV2/heroPromptCycle.ts:48,124-133,153-169 with apps/web/src/components/LandingV2/HeroPrompt.vue:28-43 · (shot + source) WCAG 2.2.2 (Pause, Stop, Hide) applies. The prompt text changes on its own, starts without user action, loops for as long as the hero is in view (about 30s per loop, repeating indefinitely, `repeat: -1`), and sits next to the headline, lede and both CTAs. It is not essential to the page. `aria-hidden` does not exempt it, because 2.2.2 also protects sighted visitors with attention or reading needs. Pausing while offscreen, on a hidden tab or during the scroll exit is not a user mechanism, and neither is the OS reduced-motion setting. The shots (`p5-v3-1440-prompt-1..6.png`, `p5-v3-1920-prompt-1..3.png`) show no control in the box. In source, `PauseReason` has no user reason and nothing in `HeroPrompt.vue` is interactive. · Fix (smallest): add a `'user'` reason to `PauseReason` and expose `setUserPaused(paused)` on `PromptCycle`. When pausing, it should call `settleAtRest(cycle)` before `hold('user', true)`, so the cycle never freezes on half-typed text. Add a small toggle button in the prompt label row next to "Prompt", outside the `aria-hidden` `.prompt__stack`. Render it only while the cycle runs (desktop, motion allowed), via a `rotating` prop from HeroScene. Its accessible name should switch between "Pause example prompts" and "Play example prompts" (or use a fixed name with `aria-pressed`). Make the target at least 24x24px with the `.lv2 :focus-visible` ring, and keep its visible state in sync.

## ADVISORY

- P5 · [ux] · heroPromptCycle.ts:12-21,74-79 · (source; arithmetic) Reading time is short. A prompt is fully on screen for 0.12 + 0.4 (light in) + 2.9 (hold) + 0.3 (dim) ≈ 3.7s, in a cycle of about 6.0s per stop. Typing runs at about 100 to 110 chars/s (1.7s for 160 to 190 chars), far too fast to read along, and the erase takes 0.55s. A 160 to 190 character prompt is about 27 to 32 words, so reading it in 3.7s needs about 450 to 520 wpm. Typical silent reading is about 230 wpm, so a visitor needs roughly 7 to 8.5s, and most will see the text erase mid-sentence. The plan set the ~6s pace, so this needs a product decision rather than holding the phase. · Fix: raise `HOLD_DURATION` to about 6s, giving about 7s fully visible and a cycle of about 9s. Alternatively keep the pace and add the hover/focus hold below, which lets a reader stop the text by resting on it.
- P5 · [ux] · HeroPrompt.vue:28-43, heroPromptCycle.ts:124-133 · (source only) Nothing happens when the pointer rests on the prompt box or the user selects its text. The cycle keeps running, so an erase rewrites the text nodes, the user's selection collapses and the read is cut off. `p5-v3-1440-cursor-over-tile.png` confirms the text keeps typing while the cursor is in use (over a tile). · Fix: add a `'reading'` hold that is on while the pointer is over `.prompt` (`pointerenter`/`pointerleave`), while focus is inside it, or while `document.getSelection()` intersects it (`selectionchange`). Settle at rest when it engages, and resume after a short delay. This is the cheap route for the reading-time issue above.
- P5 · [ux] · HeroPrompt.vue:32 · (source only, not tested in a browser) The `tw-sr-only` span with the first (hourglass) prompt sits inside the same `<p>` as the visible text. A drag or triple-click selection across the box will probably copy the hourglass prompt as well as the one shown. Nothing in the hero styles sets `user-select`. · Fix: `user-select: none` on the sr-only span, or move it out as a sibling of `.prompt__text`.

## Summary

- One blocker: the rotating prompt has no pause or stop control, as WCAG 2.2.2 requires. The smallest fix is a `'user'` pause reason plus a labelled toggle in the prompt label row, shown only while rotating.
- Each prompt is fully readable for only about 3.7s, against about 7 to 8.5s needed for 27 to 32 words. This is advisory because the plan set the pace; a hover/focus/selection hold or a longer `HOLD_DURATION` fixes it.
- Builder choices: the mid-swap jump (1), first-prompt-only screen-reader text (2) and desktop-only rotation (3) are acceptable. Choice 4, no pause control, must be fixed.
- Confirmed from shots: the absence of a pause control, the matching rims, the 390 static prompt, reduced motion, the scroll pause and text typing under an active cursor. From source only: the screen-reader and live-region check, cleanup, the gate, the selection and copy behaviour, the dim-window gap and the reading-time numbers.
