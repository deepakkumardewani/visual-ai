# Spec: Media Studio Redesign ("record collection, not a form")

Feature: `media-studio-redesign`. Branch base: `feature/media-studio`. Paths come from `REPO_MAP.md` or were verified in the repo; anything that does not exist yet is marked **(new)**.

## 1. Objective

The media-studio phases 1-5 shipped working Song, Music, Speech, Video and Tools pages on one generic template: a stacked form on the left and a dashed "Your first X" placeholder on the right, tall full-width model cards, a full-width voice list, and tools as plain forms. It reads as generic AI output. This feature redesigns the nine studio screens and turns Assets into a **Library**, without adding AI capabilities.

- **Users:** creators and hobbyists who make songs, music, speech, video and tool outputs, need to start quickly, and then find, replay and manage what they made.
- **Screens in scope:** Music (`/audio/music`, `pages/Music.vue`), Song (`/audio/song`, `pages/SongStudio.vue`), Speech (`/audio/speech`, `pages/Speech.vue`), Video (`/video`, `pages/Video.vue`), the four tools (`pages/ToolImageWatermark.vue`, `pages/ToolVideoWatermark.vue`, `pages/ToolAutocaption.vue`, `pages/ToolSketchToImage.vue`), and Assets (`/assets`, route name `APP_SURFACE.ASSETS`, rendered by `pages/Dashboard.vue` via `components/History/History.vue`), which becomes **Library**.
- **Design thesis:** one shared studio frame (composer left, this studio's generations right, persistent bottom player, centered hero composer when empty) with a purpose-built composer and result pane inside it per medium. Settings collapse into pills and popovers plus a model picker sheet. Tracks get procedural cover art and real waveforms. Motion gives feedback everywhere. Composer and collection must both reach the "joy" bar.
- **Design rules:** `.impeccable.md` (warm atelier palette, copper/gold rare, `--tw-*` tokens only, hairline borders, ease `cubic-bezier(0.16,1,0.3,1)`, 150-400 ms, opacity/transform only, `prefers-reduced-motion`). Use the impeccable skill family plus `layout`; never `frontend-design`.

## 2. Requirements

Each requirement is one testable line. "Studio" means any of the 9 screens unless named.

### 2.1 Shared studio frame
- **R1:** Replace the current template with ONE shared frame component (new, e.g. `components/Studio/StudioFrame.vue` **(new)**, built on or replacing `StudioShell.vue`) used by all 9 screens: composer column on the left, "this studio's generations" on the right, bottom player slot below.
- **R2:** The frame exposes named slots for the composer and the result stage so each studio supplies a purpose-built interior; no studio renders the dashed "Your first X" box after the redesign: `StudioEmptyState.vue` is no longer imported by any studio page or `ToolResultPanel.vue` (deleted or restyled with no dashed border), and the unused `StudioPlaceholder.vue` and its test are deleted.
- **R3:** Desktop (>= 1024 px): two columns, composer column fixed-width (about 480-560 px) and the result column filling the rest; the result column scrolls independently of the composer. Mobile (375 px): single column with a Create / Library segmented switch at the top, composer first; sticky Generate bar stays above the bottom player; no horizontal page scroll.
- **R4:** The right pane for the audio, video and tool studios is the Library component (R40) pre-filtered to that studio's media type (Song = `song`, Music = `music`, Speech = `speech`, Video = `video`; Tools = their output type, see R38), with type tabs hidden and search/sort retained. Video's pane is the stage plus this list (R32).
- **R5:** Hero state: when the user has zero generations for that studio (counted per studio, i.e. per R4 filter, after load completes), the frame shows a centered "hero composer" (large centered pill composer with a short heading and 2-3 example prompt chips from `songPresets.ts` / per-studio presets) and no right pane. For the four tools the hero is the centered stage itself (empty canvas for Sketch, upload drop stage for the watermark and caption tools) with the prompt/settings pills attached, not a text composer.
- **R6:** The hero composer settles into the split layout when the first generation job starts (not only after it completes), via a transform/opacity transition of 350-400 ms; the composer state (typed text, selected model, options) is preserved across the transition. If that first job fails, the split stays with the error state in the pane (Retry available); the hero returns only on a later visit that still finds zero generations.
- **R7:** Returning users with existing generations go straight to the split layout with no hero and no entrance replay (revisiting does not re-run intro motion).
- **R8:** The hero state never shows while generations are still loading; a quiet loading state (no shimmer skeleton) shows first, then cross-fades to hero or split.
- **R9:** Existing behaviours stay in the frame: credits cost badge beside Generate (`components/primitives/CreditCostBadge.vue`), insufficient-credits handling via `canAffordGeneration` (`utils/generationCredits.ts`), `JobProgress.vue` stage text ("Queued", "Composing", ...) with "you can leave this page", `StudioErrorState.vue` copy including "No credits were used.", `HandoffMenu.vue`, and `ShortcutsPopover.vue` (global shortcuts in `composables/useGlobalShortcuts.ts`).

### 2.2 Persistent bottom player
- **R10:** The existing `MiniPlayer.vue` becomes the bottom player: fixed to the bottom of the viewport on every route (mounted once in `App.vue`), keeps playing across navigation between studios, Library and Create, and never remounts its `<audio>` element on route change (the single element owned by `stores/player.ts`).
- **R11:** Player shows cover art, title, studio/type label, play/pause, previous/next within the current list, scrubber with waveform, elapsed/total time, volume, close; on 375 px a compact two-row layout with cover, title, play/pause, scrubber.
- **R12:** Clicking Play on any track row (Library or a studio result) starts playback instantly (the bottom player appears and starts in the same user gesture) and highlights that row as "now playing" in every list that shows it.
- **R13:** Previous/next follow the order of the list the track was started from (current filter and sort).
- **R14:** Player is audio-only (Song, Music, Speech, audio tool outputs if any). Video plays in its own preview stage (R32); starting a video pauses the player and starting audio pauses the video (both behaviours exist today in `VideoResult.vue` and must carry over to the stage).
- **R15:** Autoplay rules from the prior feature stay: nothing autoplays on load; `NotAllowedError` shows the single "Tap to play" affordance (status `blocked` in `PlayerStatus`); Media Session metadata and seek handlers stay, now including cover art.
- **R16:** The player reserves bottom space so page content and the mobile Generate bar are never covered (layout offset from a single CSS variable, not per-page magic numbers).
- **R17:** Keyboard: Space toggles play/pause (when focus is not in an input/textarea/contenteditable/modal), ArrowLeft/ArrowRight seek, existing `MEDIA_SHORTCUTS` list is unchanged; player controls are reachable by Tab in logical order.

### 2.3 Settings pills, popovers and model picker sheet
- **R18:** Each composer has a bottom row of compact pills inside the composer container (model ▾, then studio-specific pills such as lyrics mode ▾, duration/genre/mood ▾, voice ▾, resolution/duration ▾). Each pill shows its current value and opens a popover built on `components/primitives/Popover.vue`.
- **R19:** A pill whose value is automatic reads "Auto <thing>" (for example "Auto duration", "Auto genre", "Auto mood") and the popover offers Auto plus explicit choices (segmented control for duration using `SegmentedControl.vue`, drill-in rows for genre/mood).
- **R20:** Popovers open and close with opacity/transform only, close on Escape and outside click, return focus to the pill, and trap nothing (non-modal) except the model picker (R21).
- **R21:** Model selection replaces the stacked full-width model cards (`MusicModelSelect.vue`, `SpeechModelSelect.vue`, and the model controls inside `SongComposer.vue`/`VideoComposer.vue`) with one model picker for media: a modal on desktop (model list left; details and that model's settings right; primary "Use model") and a bottom sheet on mobile. Reuse `ModelPickerSheet.vue`/`ModelOption.vue` patterns where they fit; the image Create picker behaviour is unchanged.
- **R22:** The picker shows, per model: name, provider icon (`ProviderIcon.vue`), one-line strength, credit cost badge for the current options, limits (max duration/characters/lyrics length), and an unavailable/disabled reason when applicable. Choosing a model keeps draft inputs per the prior feature's model-switch rules (fields carried over, unsupported ones marked "not used by <model>", exceeded limits flagged not truncated).
- **R23:** Changing any pill value updates the cost badge within the same frame and never silently changes another pill; disabled options explain why (title/tooltip text), consistent with existing `songDisabledReason`.

### 2.4 Per-studio composers and result panes
- **R24 (Song composer):** Lyrics-first. The composer's primary surface is the section-aware lyrics editor: section headers (Verse, Chorus, Bridge, Intro, Outro, etc.) rendered as distinct labelled blocks with a copper/gold rule per type (accent used sparingly), editable inline, with add/reorder/delete section. Extends `components/Song/LyricsEditor.vue`; existing section parsing and `LyricsAiMenu.vue` generate/condense actions and character budget ("420 / 600" counter, over-budget message) remain.
- **R25 (Song lyrics panel controls):** The lyrics panel has collapse/expand, fullscreen-expand, undo and redo (keyboard Cmd/Ctrl+Z and Shift+Cmd/Ctrl+Z inside the editor; history depth at least 50), plus a "lyrics mode ▾" pill (Write myself / Auto lyrics / Instrumental) matching today's lyrics options. A separate collapsible "Styles" panel holds the style tag chips (`SONG_STYLE_CHIPS`, `StylePresets.vue`) with search and a "Your sound" summary; both panels remember collapsed state per session.
- **R26 (Song result):** `SongResult.vue` is replaced inside the frame by track rows in the right-pane Library (cover art, waveform, play). Activating a row's title (click or Enter) opens a track detail panel (desktop: inline expansion in the pane; 375 px: bottom sheet) with large cover art, prompt, style tags, lyrics view, the waveform editor entry (R30) and the overflow actions (R49). The same detail panel is used for Music and Speech rows and in Library.
- **R27 (Music composer):** Prompt-first: one large prompt field with chips for mood, genre and duration directly under it (selectable, multi-select where the model allows, search within the popover), the duration pill (`components/Music/DurationControl.vue` logic reused), model pill, and Generate with cost. Example prompt chips appear in the hero state.
- **R28 (Speech composer):** Script editor (`TtsEditor.vue` with `TagToolbar.vue`, slash tags, `TextAdvisor.vue`, `ConvertTagsDialog.vue` behaviour unchanged) as the primary surface, styled as a writing surface; voice selection becomes a horizontally scrollable strip or grid of voice cards (replacing the full-width `VoiceSelect.vue` list) showing name, a traits line (for example "warm · female · US", from the voice-traits map in R29; omitted when a voice has no entry) and a play/audition button; the selected card is marked by shape and label, not color alone, and the selected voice id sent to `/generate/audio/speech` is unchanged. (No voice cloning UI exists today; only `MAX_VOICES_PER_USER` is defined. Cloning stays out of scope.)
- **R29 (Speech audition):** Each voice card's play button plays one short pre-made clip for that stock voice through the same bottom player. Clips are static files under `apps/web/public/voice-samples/<voiceCatalog>/<voiceId>.mp3` **(new)**, listed in a manifest `apps/web/src/utils/voiceSamples.ts` **(new)** keyed by `${voiceCatalog}:${voiceId}` (the catalog is the registry's `media.voices`, e.g. `inworld`, `minimax`, as `TTS_VOICES` is keyed today) mapping to the clip path. A voice with no manifest entry shows a disabled play button with an accessible hint "Preview not available". Audition never triggers a generation, a TTS call or a credit charge.
- **R29a (Voice traits):** A static voice-traits map `apps/web/src/utils/voiceTraits.ts` **(new)**, keyed the same way, gives each stock voice up to 3 short traits (tone, gender presentation, accent/locale) rendered as "warm · female · US". It is display-only and does not change registry data or the request.
- **R29b (Asset dependency):** The clip files are a user-supplied asset: the owner records them in a manual session and adds them to `public/voice-samples/`. Agents and tests never generate them. Tests stub the manifest and serve a tiny fixture clip (or intercept `/voice-samples/*`). The feature ships correctly with an empty manifest (all play buttons disabled with the hint).
- **R30 (Waveform editor):** The waveform editor (trim, fades, volume, speed, export to WAV/MP3, save as new version via `POST /media/assets/:id/versions`) opens from a track in the studio or Library as a panel/sheet; all existing `useAudioEditor` / `useAudioExport` behaviours and copy (`EXPORT_TOO_LONG_COPY`, `HISTORY_FULL_COPY`, ...) are unchanged.
- **R31 (Video composer):** Prompt-first composer with mode tabs (Text / Image / Audio inputs as today via `ImageInput.vue`, `AudioInput.vue`, `UploadDropZone.vue`, `AttachedFile.vue`), pills for model, resolution, duration, aspect, and the `DraftToggle.vue` "Try cheap first" control retained and showing saved credits.
- **R32 (Video stage):** The right pane leads with a big preview stage (16:9 or the asset's aspect ratio, poster image, native controls styled to tokens) showing the selected/latest video; below it the Library list/grid of the user's videos pre-filtered, with the selected one highlighted. Generating state shows `JobProgress.vue` stages inside the stage with a cross-fade to the result.
- **R33 (Tools stage, general):** Each tool replaces its plain form with a stage-first layout: the stage (canvas or before/after) is the hero; settings sit in a compact pill/inspector row (desktop) or bottom sheet (375 px). Credits, validation messages and file limits from `ToolFileInput.vue` are unchanged.
- **R34 (Sketch):** `SketchCanvas.vue` + `SketchToolbar.vue` fill the stage as the primary canvas (brush, eraser, size, undo/redo, clear as today), the prompt field is a pill-style composer below/over the canvas, and the generated image appears in a before/after (sketch vs result) comparison with a draggable divider (keyboard operable). The Sketch right pane shows the user's recent images, with this session's sketch results first (kept in memory for the session), and no schema change.
- **R34a (Sketch upload):** The stage offers a Draw / Upload segmented control. Upload accepts a sketch image by drag-and-drop or file picker, JPG/PNG/WEBP only, max `MAX_IMAGE_BYTES`, using the existing image upload rule in `composables/useToolVideoUpload.ts` (`accept: 'image/jpeg,image/png,image/webp'`). The uploaded image shows in the stage and in the before side of the before/after, and Generate sends it in place of the canvas PNG. Verified: Sketch sends a `File` to `generateStore.generateImage(..., [file])`, the Create page's reference-image path, which already accepts jpg/png/webp (`inferUploadFormat`), so this needs no API change.
- **R34b (Sketch upload edge cases):** (1) Switching Draw to Upload or back keeps both the canvas strokes and the uploaded file. Generate uses the active mode's input, and Generate is disabled when the active input is empty. (2) Clear in Draw mode clears the canvas only. Upload mode has a Remove control that clears the file only. (3) A wrong file type or an oversized file is rejected before upload with the existing validation copy, and the previous input stays. (4) A very large image (pixel size over the canvas size, `SKETCH_CANVAS_SIZE`) is downscaled client-side to fit within it, keeping aspect ratio and letterboxing to the sketch aspect, before sending, so request size and cost stay as for a drawn sketch. A file that fails to decode shows "Couldn't read this image". (5) Only one file; dropping a second one replaces the first.
- **R35 (Image watermark):** Live preview on the uploaded image showing text/logo position, size and opacity as the user adjusts controls; drag to place; before/after toggle.
- **R36 (Video watermark):** Stage shows the video frame with an honest preview of the watermark at the model's real placement (fixed position, text and size only, per the prior feature's decision D4), never implying controls the model lacks.
- **R37 (Autocaption):** Stage shows the video with a caption preview overlay (style/position as supported today) and, after generation, `CaptionResult.vue` content (transcript, download) in the right pane; the burned-in captions result plays in the stage.
- **R38 (Tools outputs):** Tool outputs are saved as before (image output = image type, video output = video type; sketch results remain normal image history items, never typed `SKETCH`) and appear in each tool's right pane (filtered by that tool's feature) and in Library under Images or Videos.

### 2.6 API additions (library management only)
- **R54:** `GET /media/assets` (new query params, all optional, validated, bad values return 400 like `parseListQuery`): `feature` (one of media `FeatureType`s), `q` (case-insensitive match on title, prompt, lyrics; min 1, max 100 chars), `sort` (`newest|oldest|title|longest|favorites`; `favorites` = favorite desc then newest), `favorite=true`. Cursor semantics stay correct for each sort (compound cursor of sort key plus `_id`, so ties never skip or repeat items). Add the matching Mongo index in `models/media-asset.ts`.
- **R55:** `MediaAsset` gains `favorite: Boolean` (default false, existing documents read as false, no migration required) **(new field)**; `MediaAssetDto` gains `favorite?: boolean` (and shared type updated in `packages/shared/src/types/domain.ts`); `toMediaAssetDto` maps it. New endpoints in `routes/media.ts` behind `requireAuth` and owner checks: `PATCH /media/assets/:id` **(new)** accepting `{ title?: string (trimmed, 1-120 chars), favorite?: boolean }` with at least one field (Zod schema in `packages/shared/src/schemas/media.ts`), returning the updated DTO, and `POST /media/assets/delete` **(new)** accepting `{ ids: string[] }` (max 100) that deletes owned assets (and their Cloudinary files via `deleteMediaAsset`) and returns per-id results.
- **R56:** None of these endpoints call Replicate or charge credits; they are covered by `routes/media.test.ts` and `services/media-asset-service.test.ts` (extended) including ownership, validation and not-found cases.
- **R57:** Title of auto-named generations stays what it is today; renaming never changes `prompt`, `lyrics` or `params`.

### 2.7 Cover art and waveforms
- **R58:** Procedural cover art: a pure function (new, e.g. `utils/coverArt.ts` **(new)**, `coverArtFor(seed: string, kind)`) deterministically maps a seed (asset id plus prompt) to an abstract warm gradient/shape composition using only `--tw-*` token-derived hues (copper/gold/ember/umber family, with a limited hue offset per seed). Same seed always yields the same art; different seeds yield visibly different art; no network, no API cost.
- **R59:** Cover art renders as inline SVG or CSS gradient (new `components/Audio/CoverArt.vue` **(new)**) at 3 sizes (list 40 px, card 160 px, player 48 px), is purely decorative (`aria-hidden`, alt via the row title), and works in light and dark themes with sufficient contrast for overlaid controls (play button on hover).
- **R60:** Cover art feeds `PlayerTrack.artworkUrl` and Media Session artwork (a generated data URL or canvas blob URL), and Video/Image items keep their real poster/thumbnail instead.
- **R61:** Waveforms: audio rows and the player show a real waveform from decoded peaks (`PlayerTrack.peaks` exists). Peaks are computed client-side once per asset (Web Audio decode or the existing `useAudioEditor` bucket logic, `EDITOR_PEAK_BUCKETS`), cached in an in-memory map plus localStorage (keyed by asset id, a fixed bucket count, quantised, all access guarded by try/catch and evicted oldest-first on quota errors), computed only for rows in view (IntersectionObserver) with at most 2 concurrent decodes, and never block the first paint; while computing or on decode failure a deterministic procedural placeholder bar pattern derived from the same seed is shown. No new API field is required for v1 (Assumption 12).
- **R62:** The played portion of a waveform is tinted by progress; clicking/dragging a list waveform seeks, only for the currently loaded track; keyboard seek via the player.

### 2.8 Motion and micro-interactions
