## BLOCKING

- popup · 1. [ux] Severity: high. Focus is lost when the popup closes with Esc or the close button. `FeedbackPopup.vue:70-80` puts focus back only when `document.activeElement` is the body. The watcher runs before the leave transition, while focus is still inside the card, so focus is never put back. The card is then removed and focus falls to `<body>`. I checked this live: I focused "Earn credits", opened the popup, pressed Esc, and focus ended on BODY. A keyboard user mid-flow loses their place. Fix: put focus back when the active element is inside `cardRef` (or is the body). Capture `const inside = cardRef.value?.contains(document.activeElement)` in `onClose`, then call `restore.focus()` if `inside || activeElement === body`. For the success auto-close, do the same check before the node leaves.
- popup · 2. [ux] Severity: high. "Change" drops focus and makes Esc stop working. `FeedbackPopup.vue:174` (`@back="step = 'rating'"`) removes the focused back button and moves focus nowhere. I checked this live: after "Change", activeElement was BODY and pressing Esc did not close the popup, because the Esc handler is on the card (`:139`). The same happens on submit success: the Send button is removed and focus goes to the body. Fix: after `step = 'rating'`, use `nextTick` to focus the rating that was chosen (or the first radio), and set `FeedbackRatingScale`'s roving `focused` to the current rating. On success, focus the card (`cardRef.focus()`) so Esc still works and the live region gets announced. Also give the "Change" button (`FeedbackPopupForm.vue:31-39`, `tw-py-1 tw-text-xs`, about 24px tall) a 44px minimum touch height on the mobile sheet.
- popup+dialog · 3. [ux] Severity: medium. A rate-limited send shows misleading guidance. `submitFeedback` returns `status`, but `FeedbackPopup.vue:110-112` and `FeedbackDialog.vue:61-63` show "Couldn't send that. Your message is still here, try again." for every failure, including 429. Retrying right away will fail again (the API sends `Retry-After`), so the user is told to repeat an action that cannot work. Fix: map 429 to its own message, for example "You've sent a lot of feedback just now. Wait a few minutes, then try again. Your message is still here." The admin side already does this (useAdminFeedback.ts:81).

## ADVISORY

- 4. Popup radio group: `aria-checked` is always `false` (FeedbackRatingScale.vue:49). When the user returns via "Change", nothing shows which rating they picked. Pass the current `rating` in and set `aria-checked` and a selected style on it.
- 5. Mobile sheet height: the branch-5 sheet (popup-branch5-mobile-\*) fills about half of an 800px viewport and has no `max-height` or scroll. On short viewports, or with the iOS keyboard open, Send can be pushed off-screen. Add `max-height: calc(100dvh - 1rem); overflow-y: auto` to `.feedback-popup` under 640px (FeedbackPopup.vue:243).
- 6. Non-blocking on mobile: the sheet covers the prompt composer and Generate (popup-rating-mobile-\*). It can be dismissed, so this is fine. Consider waiting until no generation is running and the composer is not focused (the code already skips stealing focus).
- 7. Admin focus after select or back on mobile (<lg): selecting a row hides the list (`AdminFeedback.vue:86`), and "All feedback" removes the detail. In both cases focus drops to the body. Focus the detail `<article>` (`tabindex="-1"`) on select, and the originating row on back. The back button (FeedbackDetailPanel.vue:89-96, `tw-p-0`) is also under 44px.
- 8. Admin silent failures and confirmations: a failed "Copy testimonial" only logs (FeedbackDetailPanel.vue:73-76). Show "Couldn't copy" inline. Status and note saves have no "Saved" confirmation: the note button just goes back to disabled. "Copied" is not in a live region. If a status save fails, the native `<select>` can keep showing the unsaved value while the alert says it was not saved. Re-key or reset the select on error.
- 9. Error text colour `#e08585` (FeedbackPopupForm.vue:83, FeedbackDialog.vue:126, FeedbackDetailPanel.vue:163) is about 2.6:1 on the light surface-1, below AA for 14px text. It follows the existing app pattern, so add a themed danger token (a darker red in light theme).
- 10. Field focus indicator: inputs, textareas and selects use `focus:tw-ring-gold/15` plus `border-gold/55`. In the live dark screenshot this is barely visible. Raise the ring opacity (for example to /40), or use the `outline-accent` focus-visible pattern that the buttons use.
- 11. Copy: "Share feedback" (popup aria-label) and "Send feedback" (dialog title) name the same thing differently. Use one term. The popup's "Dismiss feedback" reads as dismissing the user's feedback. Use "Close" or "Not now".
- 12. Proof gaps: no shots of popup error, dialog error or rate-limited, admin loading, empty or error. I checked these in source only. The popup dark shots (popup-branch1/3/5-\*-dark) show white text fields. In the live app the textarea computes to `rgba(23,18,14,0.6)` (dark), so the shots look stale. Re-capture them.

## Summary

The dialog and admin page are solid. They follow the DESIGN.md tokens, AppModal and SegmentedControl patterns, and both have complete loading, empty, error and success states. The popup's motion floor is met: hover, active and focus-visible on every control, a 250ms enter and 150ms step cross-fade, and a reduced-motion fallback. Its radio group, labels and `aria-live` success are correct. The blockers are all in the popup's focus management (verified live with agent-browser, session closed) and the generic retry copy on 429. Spec intent (non-blocking, no trap, focus returns) is not yet met for keyboard users.
